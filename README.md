# Cardputer Duo OS starter — milestone 165

Paired ESP-IDF 5.x firmware for M5Stack Cardputer ADV (main menu, keyboard, and SD owner) and a CYD-class ESP32 board (second display). 

## Project direction
This is an evolving GUI environment, not a finished firmware release. Keep the Cardputer ADV as the keyboard/input device and SD-card host, and keep the CYD as a coordinated display. Touch remains disabled unless requested. The intended end state is a cohesive visual shell with launchable GUI apps and user-customizable SD-card scripts. Continue iterating toward it in these areas:
- Make the launcher and built-in apps feel like one GUI through shared layout, theme, and navigation conventions.
- Grow the script app model with reusable widgets and practical starter apps that users can edit on-device or from the SD card.
- Keep script authoring approachable: clear editing/validation feedback, examples, saved per-app settings, and safe app-to-app navigation.
- Preserve the two-board responsibilities and mirror behavior as features expand; Cardputer input and storage stay authoritative, CYD touch stays unused.

These are continuing development priorities, not release gates; individual features can be added and refined over multiple firmware iterations.

## Wiring (3.3 V UART signals)
Power each board from its own USB connection. Connect grounds and cross TX/RX:
- Cardputer ADV Grove GPIO1 TX -> CYD P3 GPIO35 RX.
- Cardputer ADV Grove GPIO2 RX <- CYD P5 TX (GPIO1).
- GND -> GND. Leave both 5 V pins unconnected.
- UART: 921600 baud, 8 data bits, no parity, 1 stop bit. Both boards must use matching firmware.

### Explicit pin assumptions
- Cardputer ADV Grove HY2.0-4P: GND, 5V, GPIO2, GPIO1. Firmware maps UART1 TX=GPIO1, RX=GPIO2. These are 3.3 V GPIOs; never apply 5 V UART levels.
- Cardputer ADV onboard microSD: SPI SCK=GPIO40, MISO=GPIO39, MOSI=GPIO14, CS=GPIO12. Firmware mounts it at `/sdcard` and looks for `.duo` scripts in `/sdcard/scripts`. Create that folder on the Cardputer SD card and copy scripts there. The CYD can request the catalog over UART; the Cardputer remains the only board that accesses the SD card.
- Cardputer ADV built-in display: ST7789V2, 240 × 135; backlight=GPIO38, reset=GPIO33, DC=GPIO34, MOSI=GPIO35, SCLK=GPIO36, CS=GPIO37. Built-in keyboard uses TCA8418 at I2C address `0x34`, SDA=GPIO8, SCL=GPIO9, scanned by firmware polling. All four arrow keys, Enter, and Backspace/back key are used for navigation.
- CYD inter-board UART uses P5 GPIO1 for TX and P3 GPIO35 for RX. GPIO35 is input-only, which is suitable for UART RX. Moving RX to P3 avoids P5/P1 GPIO3, which is shared with the onboard USB-to-serial bridge. The P3 pin order for the common CYD 2.8-inch board is GND, GPIO35, GPIO22, GPIO21; confirm the labels for your exact revision.
- CYD display follows the active TFT_eSPI setup: ST7789, 240 × 320 portrait, BGR color order, and 40 MHz display SPI. Its configured pins are TFT MISO=12, MOSI=13, SCLK=14, CS=15, DC=2, reset board-managed, backlight=21. The TFT_eSPI setup enables inversion, but the photographed panel output was visibly inverted with that setting, so this firmware disables inversion. Confirm display pins against the actual board revision.
- The CYD display uses upright 320 × 240 landscape orientation.

The project keeps separate configuration files for its two chips: `sdkconfig.cardputer` targets ESP32-S3, and `sdkconfig.cyd` targets ESP32. The VS Code workspaces set `IDF_TOOLCHAIN=clang`; ESP-IDF 5.5.5 marks this toolchain experimental, but it avoids the GCC internal compiler crash in the current Cardputer build. The Cardputer build is outside the long project path to avoid Windows object-path limits. Pass the matching sdkconfig file on every build, reconfigure, or flash command; do not use `set-target` on the shared project because that command regenerates the selected sdkconfig. To flash, use `idf.py -B ..\..\..\build-cardputer-clang -D SDKCONFIG=sdkconfig.cardputer -p COMxx flash` for the Cardputer and `idf.py -B build-cyd-clang2 -D SDKCONFIG=sdkconfig.cyd -p COMyy flash` for the CYD, replacing each port with the one Windows assigned. A successful CYD flash does not update the Cardputer. Use the P5/P3-to-Grove UART wiring above; keep the 5 V pins disconnected.

In VS Code, open `cardputer-duo-cardputer.code-workspace` to build or flash the Cardputer, or `cardputer-duo-cyd.code-workspace` for the CYD. Each workspace selects the matching build directory and SDKConfig file. Use UART flashing and select that board's port under **ESP-IDF: Select Port to Use**; do not rely on a fixed COM number because Windows assigns it per device and computer. JTAG flashing requires a connected and configured JTAG probe, which is not part of the documented wiring.

Connect the CYD directly to the computer with a USB data cable, select its port, then run **ESP-IDF: Flash (UART) your Project**. If the Cardputer TX wire is still on CYD P5 RX/GPIO3, disconnect that one signal wire before flashing; after flashing, connect it to CYD P3 GPIO35. CYD TX remains on P5. If auto-reset times out, hold the CYD's **BOOT** button, tap **EN/RESET**, and keep BOOT held until the flash connection starts.

Both displays use ESP-IDF's `esp_lcd` ST7789 driver. The CYD touch controller is not used by this firmware.

The line reader's destination buffer must be large enough for the complete frame plus its NUL terminator. The current firmware callers use the shared 2048-byte frame limit, so they accept payloads up to 2047 bytes; a larger frame is consumed and rejected instead of being truncated or parsed as a second message.

## Protocol
One JSON object per line. Current command dispatch recognizes `PING`, `STATUS`, `LIST`, and `RUN`; it is not a general JSON command parser. While a script runs, the Cardputer sends `script_state`, `script_text`, `script_color`, `script_rect`, `script_label`, and `script_clear` events. It sends `script_exit` when returning to the menu. The Cardputer also sends `ui_state` updates so the CYD can mirror built-in and script-defined app names, page, selection, and the saved RGB565 theme accent, plus `ui_prompt` updates for transient keyboard prompts.

```text
{"cmd":"PING"}\n -> {"type":"pong"}\n
{"cmd":"STATUS"}\n -> {"type":"status","board":"cardputer-adv","sd_ready":true,...}\n
{"cmd":"LIST"}\n -> {"type":"files","files":["example.duo"],"count":1}\n
Cardputer menu -> {"type":"ui_state","selected":0,"sd_ready":true,"page":"home","apps":["Canvas [APP]","Counter [APP]"]}\n
```

# Music player

On Cardputer-Adv builds, the Music Player app reads `.mp3` files from
`/sdcard/music`. Put MP3 files in a `music` folder at the root of the Cardputer
SD card. Use Up/Down to choose a track, Left/Right to change tracks, `B` to
switch between the Cardputer speaker and CYD Bluetooth Classic, Enter to
play/pause, Fn+Enter to stop, and Fn+` to leave the app. For Bluetooth output,
put a speaker or headphones into pairing mode before switching output. The CYD
scans for a nearby audio receiver and connects automatically. Compressed MP3
data streams over the Grove UART link; the CYD decodes it and sends it over
A2DP. Bluetooth mode supports 44.1 kHz MP3 tracks and pauses Wi-Fi/ESP-NOW on
both boards while the Music Player is open.
